# SH-01 — Login (email + password + MFA step)
Route: /login | Portal: All (tenant-branded public page) | Roles: anonymous | Density: comfortable (touch at 390)
Legacy refs: WF-01, UX-01

## Purpose
Authenticate a user into the tenant workspace, complete MFA when the org policy or user requires it, then route by role (SH-06). Tenant branding (logo, name, accent) is applied from the org resolved by subdomain; wildfire tagline removed.

## Entry points
- Direct URL / bookmark
- Session expiry redirect with `?next=<path>`
- Invite email → accept invite (SH-04) → auto sign-in
- Password reset completion (SH-03) → sign in

## Layout
- Regions: header (brandmark + help link) / main (single centered card) / footer (Powered by, legal links)
- 390: no card, full-width form, 20px gutters, sticky nothing (form is short); 768–1440: 440px card centered, 48px top offset
- MFA and backup-code steps replace card content in place (same card width); back link top-left of card

## Components used
- BulwarkInput — email (type=email, autocomplete=username), password with show/hide affordance
- BulwarkButton — primary lg full-width; `is-loading` while submitting; link variant for Forgot/Back
- BulwarkBanner — info (next notice), danger (error summary, role=alert), warning (locked), offline
- BulwarkCard — lg, 440px
- BulwarkAvatar + BulwarkCard clickable — offline cached account row

## States
| State | How it looks | Trigger |
|---|---|---|
| Default | Empty form, Sign In enabled | Load |
| Prefilled + next notice | Info banner names destination | `?next=` |
| Loading | Button spinner, fields read-only | Submit |
| Invalid credentials | One danger summary; fields not individually blamed (enumeration-safe) | 401 |
| Field validation | Summary lists problems + inline errors under fields | Client validation |
| MFA TOTP | 6 code boxes, auto-advance, auto-submit on 6th digit | Password accepted, MFA enrolled |
| MFA wrong code | Boxes error-bordered, summary explains rotation | MFA 401 |
| Backup code | Single mono input, remaining count | Link |
| Locked out | Warning banner with retry time; only Reset Password offered | 429 after N failures |
| Offline | Offline banner; cached-account rows; other sign-in disabled | navigator.onLine=false |

## Interactions
- Enter submits; Tab order email → password → show/hide → keep-signed-in → forgot → Sign In
- Code boxes: paste of 6 digits fills all; Backspace moves back; auto-submit at 6 digits
- Show/hide password toggles type; state not persisted
- Pessimistic: no optimistic transitions; button locks during request

## Validation & errors
- Email required, valid format; password required (no length hint on login)
- Auth errors never distinguish unknown email from wrong password
- After 5 failures in 15 min server returns 429 → Locked state; countdown from server time
- MFA code: 6 digits; accepts codes ±1 window

## Responsive rules
- <500: card removed, form full width, buttons 48px (touch density on `<main>`)
- Help link hidden at 390; available in footer

## Accessibility notes
- Landmarks: header, main, footer; skip link to #main
- Error summary has role=alert and receives focus on submit failure; inline errors linked via aria-describedby
- Code group: role=group with aria-label; each digit labeled
- Focus ring on all controls (`--focus-ring`); 48px targets at 390

Touch target audit (390 / touch density): inputs 48px · Sign In 48px · checkbox row 24px glyph inside 44px row · links inline text with 44px line box
