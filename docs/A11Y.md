# Accessibility: gates, patterns and the keyboard pass

Written for engineers building or changing screens. It covers what CI enforces, the
patterns components already provide, and what still needs a human check. From WP-L08
(epic `agents/epics/L09-accessibility.md`).

## What CI enforces

| Gate | Where | Fails on |
|---|---|---|
| axe on every surface | `tests/e2e/a11y.spec.ts` | Any serious or critical violation, in **light and dark** themes, on login, 404, admin dashboard, admin list, admin detail, settings, field, subcontractor portal and homeowner portal |
| axe per screen and state | `tests/e2e/screens/*.spec.ts` (`assertAxeClean`) | Serious or critical violations on each screen-contract state |
| Lighthouse accessibility | `lighthouserc.cjs` (CI job `lighthouse`) | Score below 0.95 on the ten busiest signed-in routes |
| Focus management | `tests/e2e/a11y-focus.spec.ts` | Modal focus escapes, or isn't restored; focus not moved after a route change |
| Async errors | `tests/e2e/a11y-async-errors.spec.ts` | Failed invite, COI upload or avatar upload without an announced error and a working retry |
| Field tabs | `tests/e2e/field-tabs.spec.ts` | Duplicate or dead tab links; missing `aria-current` |

`ALLOW` in `a11y.spec.ts` is for tracked exceptions only. It is empty today. Each entry must
name the work package that removes it.

## Patterns to reuse (don't reimplement)

- **Dialogs:** use `BulwarkModal` or `BulwarkDrawer`. Both provide `role="dialog"`,
  `aria-modal`, a generated title id for `aria-labelledby`, initial focus on the first body
  control, a Tab trap, Escape to close, and focus restored to the opener (`useFocusTrap`).
  Don't build ad-hoc `fixed inset-0` overlays; the invite modal was one and has been migrated.
- **Inputs:** `BulwarkInput` provides the label `for`/`id` pairing, `aria-invalid`, and
  `aria-describedby` pointing at the error or hint, with the error rendered as
  `role="alert"`. A raw `<select>` or `<textarea>` needs its own `<label for>`.
- **Async failures:** show a persistent inline message with `role="alert"` (a toast alone
  disappears), keep the user's input, and offer "Try again" that repeats the same request.
- **Route changes:** `app/plugins/route-focus.client.ts` focuses the new page's `h1`
  (or `main`). Give every page one `h1`. Query-only changes, such as filters, keep focus
  where it is.
- **Skip links and landmarks:** every layout starts with a "Skip to content" link and has
  exactly one `<main>`.
- **Color:** status must not rely on color alone; pair it with text or an icon. Use the
  semantic token utilities. In dark theme the legacy `text-primary` foreground is remapped
  to Packet A's teal (`legacy-compat.css`) until WP-A2 replaces the legacy utilities.

## Keyboard pass

**Automated** (runs in CI): modal open, Tab cycling, Shift+Tab, Escape and focus restore;
navigation from a sidebar link, with focus landing on the new page's heading.

**Parked until the rebuilt screens ship (2026-09-30, sponsor).** Every journey below runs through
legacy screens that the Packet A–D rebuild (WP-A2 onward) replaces, so a pass now would test code
about to be thrown away. The launch gate (WP-L16) owns it; run it against the rebuilt screens.
Automated coverage meanwhile: axe on every surface in both themes, focus trap/restore, route
focus, skip link, aria-invalid (tests/e2e/a11y*.spec.ts).
