- **Date:** 2026-05-14
- **Wave:** Phase 1 Hardening
- **ADR:** [ADR-0013](../decisions/ADR-0013-gc-generalization-programs.md)

## Shipped

- **Schema** — `server/db/schema/programs.ts` + `server/db/schema/program_memberships.ts` (+ enum `program_kind`). Migration via `pnpm db:generate`.
- **Contracts** — `shared/contracts/program.ts` with `ProgramSchema`,
  `ProgramCreate/Update/List` inputs, `ProgramAssign/Unassign`, and
  `IProgramService`.
- **Mock service** — `shared/mocks/program.mock.ts`, seeded with one
  builtin Wildfire Retrofit program per fixture org. Wired into
  `shared/mocks/factory.ts`.
- **Real service** — `server/services/program.real.ts` with
  `assertSameTenant` + `withAudit` on every mutation, friendly
  duplicate-slug error, builtin-delete guard. Wired into
  `server/utils/services-factory.ts`. RPC route via the existing
  generic `[service]/[method].post.ts` dispatcher — no new files in
  `server/api/services/program/` needed.
- **Seed** — `scripts/db-seed.mjs` inserts a Wildfire Retrofit row per
  demo org under the existing wipe-and-replace transaction. Idempotent.
- **Admin UI** — `app/pages/settings/programs.vue` (role gated to
  `ROLE_GROUPS.admin`). New card on the Settings hub
  (`app/pages/settings/index.vue`).
- **Tests** —
  - Unit: `tests/unit/program.test.ts` (7 specs)
  - E2E: `tests/e2e/settings-programs.spec.ts` (5 specs)
  - Bumped Settings card counts in `tests/e2e/settings-matrix.spec.ts`
    (org_admin 8→9, super_admin 9→10).

## Hooks for downstream waves

- **W2-2 (inspection template engine).** `programs.inspectionTemplateId`,
  `standardSetId`, and `complianceDocTemplateId` are already columns
  on the row, nullable. No new migration needed.
- **W1-3 (admin pipeline editor).** Read
  `programs.defaultTradeSlots` to scaffold a quote / WO with the right
  trade slot list. Pricing-builder reads `pricingDefaults` for markup,
  tax, and quote expiry.
- **EH-B / W1-2 (CMS labels).** Per-program label keys (e.g.
  `program.wildfire-retrofit.quote_cta`) can layer on top of the
  program slug; no contract change needed here.
- **E13 (homeowner portal).** "What programs is my property in?"
  resolves with a single `programMemberships` query on
  `(organizationId, entityType='property', entityId)`.

## Out of scope (deferred to W2-2 / later)

- Editing inspection templates from the Programs admin screen.
- Cloning a program into another org (would require a super-admin
  flow + careful FK rewrite).
- Membership assignment UI on the property/quote/work-order detail
  pages — the service supports it but no UI consumes it yet.

## Deviations from the task spec

- Task spec mentioned creating per-method API route files under
  `server/api/services/program/*.post.ts`. The existing pattern is a
  single generic dispatcher (`server/api/services/[service]/[method].post.ts`)
  that dispatches by service+method name. Registering `program` in
  `BulwarkServices` is sufficient. No new route files were needed.
