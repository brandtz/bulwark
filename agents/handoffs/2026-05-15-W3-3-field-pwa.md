# W3-3 — Field / Mobile / PWA — Handoff

- **Date:** 2026-05-15
- **Slice:** W3-3 / EH-M
- **ADR:** [ADR-0029](../decisions/ADR-0029-field-pwa-and-offline.md)
- **Status:** DONE

## TL;DR

Bulwark now has a real field surface at `/field`. A field-only layout
hosts five new pages (My Day, Job detail, Inspect, Photos, free-roam
Check-in), all role-guarded by `app/middleware/field-role.ts`. The
shell is installable to the home screen via a **hand-rolled** PWA
(manifest + service worker, zero new npm deps). Check-ins land in
`audit_log` (action `state_change`, metadata.kind `field.check_in` /
`field.check_out`). Offline writes have a `localStorage` queue seam
that Phase 2 can swap for IndexedDB + the Background Sync API
without touching call sites.

## Offline queue seam — promotion path

**v1 shape (this slice):**

```ts
// app/composables/useOfflineQueue.ts
type Entry = { url: string; method: 'POST' | 'PATCH' | 'DELETE'; body: unknown }
// keyed `bulwark.offline.<userId>` in localStorage.
// drain() FIFO POSTs each entry; listens to window 'online' event.
```

**v2 (Phase 2, deferred):**

1. Move storage to **IndexedDB** inside the service worker (cross-tab,
   survives SW restart).
2. Register a **Background Sync** tag (`'bulwark.offline'`) on each
   enqueue.
3. SW listens for `sync` events and drains directly — works even when
   no tab is open.
4. Reconciliation: replay rejected entries through the existing
   audit_log / domain event bus, surface conflicts in the field
   notification feed (W3-1).

The composable's public surface (`enqueue/drain/size`) does not change
when this promotion lands.

## Known gaps / deferred polish

1. `listForFieldUser` does NOT yet filter by `userId` (the slot-level
   assignment check). It returns all WOs in the date range for the org.
   Easy follow-up; the unit test pins the date filter so a future
   change is safe.
2. **Geofence-validated check-ins.** v1 stores raw lat/lng floats in
   `audit_log.metadata`. A "did the user actually arrive at the
   property" gate is a future ADR — does not change the storage shape.
3. **Photo upload backend.** Stores a dataURL in `propertyPhotos.url`
   for v1; swaps to a pre-signed S3 PUT once W3-1 storage lands.
4. **Pull-to-refresh.** Native gesture, not in scope. The refresh
   button is the workaround.
5. **Push notifications on the field surface.** Lives behind W3-1's
   in-app notifications; a future slice adds Web Push registration in
   `pwa.client.ts`.
6. **Per-user slot-aware My Day filter.** Currently any field user in
   the org sees every today-scheduled WO. A trivial follow-up once
   tradeSlots.assignedToUserId becomes a hot path.
