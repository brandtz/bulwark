## What does NOT land here

- **Logo upload.** The branding form accepts a public image URL. R2
  upload widget is tracked for Wave 2 alongside the rest of the
  storage UX. Render the URL preview is sufficient for Phase 1.
- **PDF + email surface adoption.** Defaults exist
  (`pdf.footer.default`, `email.subject.quote_sent`, …) but the
  templates that render them aren't yet wired to `useLabel()`. Wave 2
  rolls the composable into quote/invoice PDFs and the email subject
  generators. One-line edits, no schema changes.
- **Translations.** Schema includes a `locale` column but only `en-US`
  is wired end-to-end. Adding `es-MX` is a data-only change once a
  customer asks.
- **Per-service RPC route.** The generic dispatcher at
  `server/api/services/[service]/[method].post.ts` already routes the
  new service. Adding `server/api/services/label/[method].post.ts`
  would be a no-op shim and was skipped intentionally.

## Gotchas the next subagent will hit

1. **`StatusBadge.vue` only handles `PropertyStatus`** in the current
   codebase. Other status pills (quote, invoice, WO) render directly
   from `*_STATUS_LABEL` maps in their own components. Wave 2 should
   either (a) extend `StatusBadge` to dispatch over the broader status
   union and `useLabel()` once, or (b) replicate the
   `tLabel('status.<domain>', ...)` pattern in each callsite. Pick one
   before the third status surface needs a rename.
2. **Empty-string overrides** are treated as absent in
   `resolveLabel()`. The editor blocks empty on save (`dirtyRows`
   filters out `trim() === ''`), but the resolver doubles down on
   that contract.
3. **Branding `getBranding()` returns a synthesized row** when no
   `org_branding` row exists. The first save is an upsert that
   materializes the row. Don't add a `null` branch in callers — the
   contract guarantees a row.
4. **`BulwarkInput`/`BulwarkSelect` don't forward `data-testid` to the
   inner control** — Vue applies non-prop attrs to the root element
   (the wrapper div). The e2e spec scopes by `getByTestId('...')` then
   queries `input`/`textarea` inside. Mirror that pattern when adding
   assertions.
