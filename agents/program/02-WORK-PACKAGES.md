# 02 — Work Packages: how to read and maintain the registry

> **Source of truth:** `work-packages.json` (validated by `work-packages.schema.json`).
> **Dashboard:** `agents/codegraph/work-packages.md` (regenerated by `pnpm codegraph:build`).
> **Per-package view:** `pnpm codegraph:query -- wp WP-B2`.

## Anatomy of a WP

| Field | Meaning | Who edits |
|---|---|---|
| `id`, `title`, `lane`, `phase`, `size` | identity and planning | architect |
| `goal`, `scope[]`, `outOfScope[]` | what "done" builds; what is explicitly not touched | architect |
| `designs[]` | design IDs this WP implements; must be `received` unless `designAhead: true` | architect |
| `files[]` | globs the WP may edit — ownership boundary enforced when `in-progress` | architect (agent may propose additions via PR to this file) |
| `acceptance[]` | observable outcomes, each requiring at least one negative test | architect |
| `tests[]` | test files to create/extend | architect; agent may add |
| `dependsOn[]` | WPs that must be `done` first | architect |
| `decisions[]` | ED ids to honor | architect |
| `status`, `owner`, `branch`, `pr` | lifecycle | implementing agent |
| `agentNotes` | gotchas, pointers | anyone |

## Lifecycle

```
todo ──(deps done + designs received/designAhead)──▶ ready ──(agent claims: owner+branch)──▶ in-progress
   ──(tests green, screen:audit ok, codegraph ok)──▶ review ──(skeptic: 0 P0/P1)──▶ done
                                                     └──(P0/P1 found)──▶ in-progress
blocked = waiting on external input (design packet, sponsor decision) — note the blocker in agentNotes
```

`pnpm codegraph:check` fails when: a WP is `in-progress`/`review` with unfinished deps or
un-received designs (without `designAhead`), when two `in-progress` WPs overlap on files, or
when a `done` WP touches a page with no e2e coverage.

## Adding or splitting a WP

1. Architect adds the object to `work-packages.json` following the schema.
2. Keep IDs stable; split XL packages as `WP-A4a`, `WP-A4b`… (schema allows `WP-[A-Z]+[0-9]*`,
   so use `WP-A4A`/`WP-A4B` or new numbers — prefer new numbers with `dependsOn` chains).
3. Run `pnpm codegraph:build && pnpm codegraph:check`; commit the regenerated graph.
